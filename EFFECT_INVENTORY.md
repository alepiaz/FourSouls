# Base Game V2 capability inventory

Use this index to choose engineering work. The [batch 055 audit](BASE_GAME_V2_AUDIT.md) owns card text, variants, conditions, costs, selectors, durations, rule questions and card-specific regressions. [Architecture and execution traces](IMPL_STATUS.md) explain the integration points. [Delivery order and exit tests](ROADMAP.md) assign the work. All evidence below is relative to the pinned Sprint 14 tree unless explicitly marked merged.

## What the numbers measure

The 370 audit rows (including setup, keywords, reward boxes and designs without a printed ability) contain **287 distinct representative design IDs**. Use the exact backticked `b2-…` key in the first column. Several identical names denote different effects. The 340 physical catalog entries include 53 additional copies awaiting exact mapping. Twenty representative IDs remain provisional. Neither multiple abilities, physical copies, promo The Bloat nor Four Souls+ V2 Bony and Headless Horseman increase the design denominator.

| Independent question | Baseline disposition | What changes the answer |
|---|---|---|
| Does the engine perform this behavior? | Record shared YAML, legacy/card-specific, partial/probe, or missing per capability below. Four audit rows verify the setup path for Isaac, Maggy, Cain and Eve. | A working producer and consumer with the correct controller, timing, targets, outcome, and cleanup. |
| Can this design enter normal play? | See the wiring table. A demo slot or starting item can expose a stub, a different printing, or incorrect data. | Match the edition, load its definition, include physical refs in the selected deck/setup, and expose any required action to the actor. |
| Has the whole design been verified? | All 287 have an open implementation or verification task in batch 055. **0/287 certified by this audit**. Existing acceptance tests establish narrower behavior. | Resolve each row and shared interaction for the design and pass a normal-play regression covering the printed behavior. |

For a milestone, take the union of requirements across **all** rows of each design, including normal action/trigger, choices and shared lifecycle. Compare eligible design sets before and after the milestone and subtract IDs already eligible. Track newly *wired* and newly *verified* separately. A count of rows routed to a mechanic is workload, never an unlock forecast. This documentation change adds zero playable designs.

## Content that can be authored immediately

**First demo pack:** A Dime!! uses legacy `gain_cents` with amount 10. Dip, Pale Fatty and Red Host use only numeric monster stats and fixed coin rewards. All four are absent from both relevant registries and demo pools. Clotty already ships and needs a data correction (2 HP, DC 3, ATK 1, four cents). These are **four proposed new demo designs and one repair**. They need no new effect builder. Common response windows, replaceable gains and death timing still gate all-interaction certification. See [the next sprint](ROADMAP.md#next-playable-milestone).

Fatty, Leech, Pooter and Squirt can use the existing fixed single-loot schema. Conjoined Fatty and Trite also fit the schema but can fail after death has already mutated the board if a two-card reward meets a one-card deck. Fat Bat needs consistent treasure entry, Gurdy and Little Horn need a unique soul destination, and Cod Worm needs a zero-damage regression before release. Keep these in the follow-on pack. Fly, Spider and Monstro already have definitions and are regression anchors.

## When more cards become eligible

| Candidate | Capability conjunction to check before promoting the whole design | Evidence still owed |
|---|---|---|
| A Dime!! | Existing gain factory + real deck entry for demo play. For full V2: legal loot window, correct priority, shared replaceable coin gain, cancellation/discard. | Actual and canceled play, off-turn, interaction with gain modifiers. |
| Cursed Gaper | Final roll + game-controlled trigger + resolution-time group + beneficiary incarnation/expiry + ordinary monster lifecycle. | Group changes across response and zone changes, repeated rolls, end of turn. |
| Holy Dinga | Universal roll + captured roller + player heal (PR #6) + separate variable coin reward roll and normal death stages. | Roll to heal the off-turn roller, then roll for reward; each qualifying result is observed once. |
| Wizoob | Own-death event + staged death + two owners at two times + origin-aware soul destruction + loot-three and refill. Bonus-enabled profiles require R22 retirement. | Scripted command-path kill and decisions, with a short loot deck and a changed soul area. |
| Lost Soul | Loot resolution + trinket item entry + triggered conversion + origin, soul value and win check. | Cancel before entry vs destroy after conversion, with each physical ref in exactly one zone. |
| Polydactyly | Live own-turn loot allowance **and** first-attack-roll ATK, with roll ordinals, transfer and turn expiry. | Miss, reroll, mid-turn acquisition and two simultaneous copies. |

These release gates narrow the workload. An engineer can add a candidate to the demo earlier if its remaining interaction limits are recorded. Publish the strict newly eligible count only after checking the complete audit rows by design ID.
